## Notes de réunion

### 1. Aperçu du projet (Marie Dupont)

**Contexte:**
- CryptoInvest SA doit optimiser l'allocation de portefeuille entre les actifs cryptographiques
- Utilise actuellement une analyse manuelle basée sur Excel (prend du temps, sujette aux erreurs)
- Objectif : Automatiser la collecte, l'analyse et l'optimisation de portefeuille de données

**Objectifs commerciaux :**
- Réduisez le temps de collecte manuelle des données de 90 %
- Fournir des recommandations de portefeuille mises à jour quotidiennement
- Améliorer les rendements ajustés au risque (cible Sharpe > 1,0)

**Critères de réussite :**
- Pipeline quotidien entièrement automatisé
- Accès API pour les applications en aval
- Documentation pour la conformité réglementaire

### 2. Discussion sur la portée (Jean Martin)

**Dans le champ d'application :**
- Ingestion de données depuis l'API Binance
- Stockage des données dans l'architecture Data Lake
- Calcul de métriques financières (rendements, volatilité, corrélations)
- Optimisation du portefeuille Markowitz
- API REST pour l'accès aux données
- Orchestration des flux d'air

**Hors de portée :**
- Exécution des transactions en temps réel
- Prédictions d'apprentissage automatique
-Application mobile
- Prise en charge multi-devises (USD uniquement)

**Décision :** Portée approuvée par le propriétaire du produit.

### 4. Approche technique (Laien Wu)

**Architecture proposée :**
- Data Lake avec zones Bronze/Argent/Or
- Format Parquet pour le stockage (en colonnes, efficace)
- DuckDB pour l'analyse SQL (sans serveur, rapide)
- FastAPI pour les points de terminaison REST
- Docker pour le déploiement
- Airflow pour orchestration

**Décisions techniques clés :**
1. **Pas de pandas** - Utilisez PyArrow directement pour les performances
2. **DuckDB sur PostgreSQL** - Plus simple, pas de gestion de serveur
3. **Parquet sur CSV** - Compression, application du schéma
