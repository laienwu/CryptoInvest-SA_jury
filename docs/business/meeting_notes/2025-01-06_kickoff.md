## Meeting Notes

### 1. Project Overview (Marie Dupont)

**Context:**
- CryptoInvest SA needs to optimize portfolio allocation across crypto assets
- Currently using manual Excel-based analysis (time-consuming, error-prone)
- Goal: Automate data collection, analysis, and portfolio optimization

**Business Objectives:**
- Reduce manual data collection time by 90%
- Provide daily updated portfolio recommendations
- Improve risk-adjusted returns (target Sharpe > 1.0)

**Success Criteria:**
- Fully automated daily pipeline
- API access for downstream applications
- Documentation for regulatory compliance

### 2. Scope Discussion (Jean Martin)

**In Scope:**
- Data ingestion from Binance API
- Data storage in Data Lake architecture
- Financial metrics calculation (returns, volatility, correlations)
- Markowitz portfolio optimization
- REST API for data access
- Airflow orchestration

**Out of Scope:**
- Real-time trading execution
- Machine learning predictions
- Mobile application
- Multi-currency support (USD only)

**Decision:** Scope approved by Product Owner.

### 4. Technical Approach ([Your Name])

**Proposed Architecture:**
- Data Lake with Bronze/Silver/Gold zones
- Parquet format for storage (columnar, efficient)
- DuckDB for SQL analytics (serverless, fast)
- FastAPI for REST endpoints
- Docker for deployment
- Airflow for orchestration

**Key Technical Decisions:**
1. **No pandas** - Use PyArrow directly for performance
2. **DuckDB over PostgreSQL** - Simpler, no server management
3. **Parquet over CSV** - Compression, schema enforcement
